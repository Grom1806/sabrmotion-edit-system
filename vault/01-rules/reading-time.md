# Время чтения

Пользователь (2026-10-20): «сцены заканчиваются очень быстро, не успеваю читать».

**Норма:** смысловой текст после того, как ПОЛНОСТЬЮ появился, держится на экране не меньше
`1.2 с + 0.3 с × слов`, плюс **+0.5 с** для чисел, сумм и UI-экранов, **+1 с** для главного тезиса и CTA. Только потом уходит.

- Скорость самих анимаций (побуквенная волна, проезды, попы) **не замедлять** — удлинять паузу-держание.
- Во время держания камера может медленно дрейфовать (2–3 %), ничего нового не появляется.
- Ролик выйдет длиннее референса — это нормально.
- Если на экране несколько надписей сразу, считать слова всех смысловых надписей экрана (мелкие служебные подписи UI — по смыслу).

**Как делать в AE** (пример: `ae/build_perset05.jsx`, PERSET 05): монтаж собирается в исходном темпе, внешняя комп «ФИНАЛ (держание текста)» вкладывает его с Time Remap: в каждой точке держания исходник медленно ползёт по окну [tA, tB] (только дрейф камеры), длительность держания E ≥ норма − уже видно − окно + 0.1 с. Карта времени пишется в `audio/holds.json`, микшер пересчитывает по ней время каждого звука.

**QA:** таблица «надпись → слов → норма → видна, с → ок» (`qa/reading_time.md`), все строки «да».

## Уточнение 13:34 (2026-10-20)
Пользователь: «когда сцена заканчивается, она ждёт очень долго — сделай быстрее, не настолько медленно; сделай озвучку; переходы сцен быстрее».
- **С голосом:** надпись держится, пока звучит её фраза, **+0.3 с**.
- **Без голоса:** мягкая норма **0.6 с + 0.2 с/слово** (+0.3 числа/UI, +0.6 CTA). Норма 1.2 + 0.3/слово выше — отменена как слишком медленная.
- **Переходы 0.3–0.5 с**, без пустых (чёрных) кадров между сценами; следующая сцена может начинаться под хвост фразы.
- SFX под голосом приглушать (тики букв −6 дБ, остальное −3 дБ), голос всегда разборчив; без музыки; мастер −14 LUFS.
- Ориентир длины: голос + 1–2 с. PERSET 05: 108 → 83 с (голос 53.5 с, 23 фразы).

## Темп = как в референсе (2026-10-20 13:49, главнее норм выше)
Пользователь: «Сделай скорость изменения как в референсе — насколько у них быстро, так же у нас».
- Если есть референс, длительность каждой сцены и переходов копируется с него (±10 %). Удлинённых держаний через Time Remap нет.
- Если текст при таком темпе не читается — **сокращать сам текст** (меньше слов, ключевое слово крупнее), а не время. Пример PERSET 05: тосты сцены 02 — 3 штуки, только заголовки.
- Озвучка пишется короткими фразами под длительность сцен; фраза не растягивает сцену (можно speed 1.15, начало под хвост прошлой сцены).
- QA: таблица «сцена: референс → у нас» (`qa/tempo.md`). PERSET 05: 52.13 → 51.40 с.
- Нормы 1.2 + 0.3/слово и 0.6 + 0.2/слово выше действуют только для роликов без референса по темпу.

См. [[rhythm-v2]], [[motion-v3]], [[ref-ui-card-build]].

## Автопроверка (с 2026-10-25)
Пользователь: «проверяй каждый, чтобы человек успел увидеть эту сцену и читать внутри текста».
- `node tools/readcheck/readcheck.mjs <папка композиции>` (репозиторий sabrmotion-edit-system) запускать после сборки и **до** показа.
- Что делает: перематывает HyperFrames-таймлайн кадр за кадром и меряет каждую надпись (видна целиком и стоит на месте) по нормам выше.
- Субтитр: от первого слова до ухода ≥0.15 + 0.2 с/слово. Вставка ≥1.0 с.
- Наезды двух надписей помечаются `OVERLAP`.
- Ноль FAIL/OVERLAP обязателен. Исключение (например, субтитр, который переходит в слово-героя) записать в урок.
- Контраст программа не видит: последний кадр каждой сцены проверять глазами.
- Для AE: те же нормы по таблице «надпись → полностью видна → уходит» из build.jsx.
